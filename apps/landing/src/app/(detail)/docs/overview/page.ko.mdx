## Devup UI란?

**Devup UI는 단순히 또 하나의 CSS-in-JS 라이브러리가 아닙니다. CSS-in-JS의 미래를 제시합니다.**

Devup UI는 Rust와 WebAssembly로 구현한 제로 런타임 CSS-in-JS 전처리기입니다. 빌드 시점에 모든 스타일을 변환하여 런타임 오버헤드를 완전히 없애면서 CSS-in-JS 문법을 폭넓게 지원합니다.

### 기존 CSS-in-JS의 문제점

기존 CSS-in-JS 솔루션에서는 다음 두 가지 중 하나를 선택해야 했습니다.

- **개발자 경험**: 직관적인 API, 컴포넌트와 같은 위치에 작성하는 스타일, 동적 테마
- **성능**: 런타임 오버헤드 제거, 빠른 페이지 로딩, 최적의 Core Web Vitals

styled-components나 Emotion 같은 라이브러리는 뛰어난 개발자 경험을 제공하지만, 스타일을 생성하기 위해 런타임에 JavaScript를 실행합니다. Vanilla Extract 같은 제로 런타임 대안은 성능을 위해 유연성 일부를 포기합니다.

### Devup UI의 해결 방식

Devup UI는 이 둘을 모두 제공합니다. Rust 기반 전처리기가 빌드 시점에 코드를 분석하고, 정적으로 알 수 없는 값은 CSS 변수로 처리하거나 문제가 있는 위치를 알려 주는 빌드 오류를 발생시킵니다([지원 문법과 제한 사항](/docs/limitations)).

- **변수** — 동적 값을 CSS 사용자 정의 속성으로 변환합니다.
- **조건식** — 삼항 표현식을 정적으로 분석합니다.
- **반응형 배열** — 브레이크포인트별 스타일을 미리 생성합니다.
- **의사 선택자** — `_hover`, `_focus`, `_active`를 자연스럽게 사용할 수 있습니다.
- **테마** — 타입이 안전한 테마 토큰과 추가 런타임 비용 없는 테마 전환을 제공합니다.

### 동작 원리

```tsx
// 익숙한 CSS-in-JS 문법으로 작성합니다.
const example = <Box _hover={{ bg: 'blue' }} bg="red" p={4} />

// Devup UI가 빌드 시점에 변환합니다.
const generated = <div className="a b c" />

// 최적화된 원자적 CSS를 함께 생성합니다.
// .a { background-color: red; }
// .b { padding: 16px; }  /* 4 * 4 = 16px */
// .c:hover { background-color: blue; }
```

> 숫자 값에는 4를 곱합니다. `p={4}`는 `padding: 16px`로 변환됩니다.

클래스 이름에는 짧은 37진법 인코딩(`a`, `b`, ... `z`, `_`, `aa`, `ab`, ...)을 사용하여 CSS 출력 크기를 최소화합니다.

### 익숙한 API

styled-components나 Emotion을 사용해 봤다면 익숙하게 느껴질 것입니다.

```tsx
import { styled } from '@devup-ui/react'

const Card = styled('div', {
  bg: 'white',
  p: 4, // 4 * 4 = 16px
  borderRadius: '8px',
  boxShadow: '0 4px 6px rgba(0, 0, 0, 0.1)',
  _hover: {
    boxShadow: '0 10px 15px rgba(0, 0, 0, 0.1)',
  },
})
```

Tailwind 쪽은 첫 문단과 버튼에 스타일을 더 많이 적용하고, Devup UI 쪽은 타입이 지정된 컴포넌트와 스타일 속성을 사용합니다. 따라서 이 결과는 개별 CSS 규칙의 마이크로벤치마크가 아닌 빌드 파이프라인의 측정 결과로 해석해야 합니다. 정적 `.css.ts` 항목은 정적 모듈에 사용하던 이전 `lite` 고속 처리 경로로 측정했습니다. 현재는 모든 `.css.ts` 모듈이 전체 Boa 평가기에서 실행되며, 첫 모듈에는 약 20ms, 이후 모듈마다 1ms 미만이 추가됩니다.
