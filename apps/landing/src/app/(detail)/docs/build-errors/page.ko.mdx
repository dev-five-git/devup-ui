# 빌드 오류

Devup UI는 스타일링 런타임을 배포하는 대신 스타일을 CSS로 빌드합니다. 이 레퍼런스는 검토한 추출기와 플러그인 소스가 출력하는 진단 메시지를 실패하는 입력 및 허용되는 수정 예시와 함께 분류해 정리합니다. 더 넓은 지원 범위와 합성 규칙은 [지원 문법과 제한 사항](/docs/limitations)을 참고하세요.

위치가 표시된 스타일 진단 메시지는 다음과 같은 형태입니다.

```text
<file>:<line>:<column>: <API> cannot use `<code>` at build time: <requirement>
```

자리 표시자는 소스에 따라 달라집니다. 아래의 요구 사항 문구는 바꿔 쓴 것이 아니라 실제로 출력되는 문구입니다. 진단 메시지는 `Cannot compose`, `Cannot place`, 제거된 런타임 바인딩, 잘못된 형태를 보고하기도 합니다. 스타일 진단 메시지는 원본 소스 위치를 가리킵니다. 내부 로더/설정 메시지는 별도로 정리되어 있습니다.

각 예시는 별개의 컴파일러 입력입니다. `width`, `rules`, `value`, `getStyles` 같은 이름은 코드에서 선언하지 않는 한 런타임에만 제공되는 값을 뜻합니다. 알려진 요소 선언 안의 동적 값은 CSS 변수가 될 수 있지만, 알 수 없는 규칙 키나 내용을 알 수 없는 스타일 객체 전체는 그럴 수 없습니다.

여러 작성 방식이 공유하는 메시지 유형은 해당 API들에서 그대로 재사용됩니다. 제시된 수정 전/후 예시는 소스별 WASM 빌드에서 검증했습니다. 클래스 이름과 생성되는 변수 이름은 안정적인 공개 식별자가 아닙니다.

## 스타일 props

### 알 수 없는 선택자 스타일 객체

**API:** 스타일 props. **메시지 형식:**

```text
`<Box>` cannot use `<code>` at build time: its styles must be an object literal or a constant object, or be computed from constants
```

**발생 조건:**

{/* probe: selector-object before */}

```tsx-error
import { Box } from '@devup-ui/react';
export const App = ({ rules }) => <Box _hover={rules} />;
```

**원인:** 선택자에는 알려진 속성 집합이 필요합니다. 내용을 알 수 없는 런타임 객체에서는 빌드가 추출할 선언을 얻을 수 없습니다.

**해결:** 객체 구조를 명시적으로 작성하세요. 개별 값은 동적으로 남아 CSS 변수가 될 수 있습니다.

{/* probe: selector-object after */}

```tsx
import { Box } from '@devup-ui/react'
export const App = ({ color }) => <Box _hover={{ color }} />
```

### 잘못된 선택자 이름

**API:** 스타일 props. **메시지 형식:**

```text
`<Box>` cannot use `<code>` at build time: a selector key names a pseudo-class or pseudo-element, as `_hover` or `hover`, or is a selector, as `&:hover`, `& > p` or `.parent &`
```

**발생 조건:**

{/* probe: selector-name before */}

```tsx-error
import { Box } from '@devup-ui/react';
export const App = () => <Box _notASelector={{ color: 'red' }} />;
```

**원인:** 알 수 없는 의사 선택자 이름은 빌드가 출력할 수 있는 CSS 선택자가 아닙니다.

**해결:** 지원되는 의사 선택자나, &:hover처럼 &를 포함한 완전한 선택자를 사용하세요.

{/* probe: selector-name after */}

```tsx
import { Box } from '@devup-ui/react'
export const App = () => <Box _hover={{ color: 'red' }} />
```

### 클래스 문자열은 선택자 CSS 텍스트가 아님

**API:** 스타일 props. **메시지 형식:**

```text
`<Box>` cannot use `<code>` at build time: a selector takes styles, an object such as `{ color: 'red' }` or CSS text such as `color: red`
```

**발생 조건:**

{/* probe: selector-css-text before */}

```tsx-error
import { Box } from '@devup-ui/react';
export const App = () => <Box _hover="external-class" />;
```

**원인:** 선택자는 외부 클래스 이름이 아니라 선언을 받습니다.

**해결:** 스타일 객체나 color: red 같은 유효한 CSS 선언 텍스트를 전달하세요.

{/* probe: selector-css-text after */}

```tsx
import { Box } from '@devup-ui/react'
export const App = () => <Box _hover={{ color: 'red' }} />
```

## css / globalCss / keyframes

### css()의 런타임 값

**API:** css / globalCss / keyframes. **메시지 형식:**

```text
`css()` cannot use `<code>` at build time: its values must be literals, theme tokens or constants, or be computed from them
```

**발생 조건:**

{/* probe: static-css before */}

```tsx-error
import { css } from '@devup-ui/react';
export const card = css({ width });
```

**원인:** 이 API는 스타일시트 규칙을 출력하므로 런타임 CSS 변수를 설정할 요소가 없습니다.

**해결:** 리터럴, 테마 토큰, 상수 또는 상수로부터의 결정적 계산을 사용하세요. 런타임 값이라면 선언을 스타일 prop으로 옮기세요. 예: &lt;Box w=\{width\} /&gt;.

{/* probe: static-css after */}

```tsx
import { css } from '@devup-ui/react'
export const card = css({ width: '20px' })
```

### 알 수 없는 전역 규칙 객체

**API:** css / globalCss / keyframes. **메시지 형식:**

```text
`globalCss()` cannot use `<code>` at build time: its values must be literals, theme tokens or constants, or be computed from them
```

**발생 조건:**

{/* probe: global-object before */}

```tsx-error
import { globalCss } from '@devup-ui/react';
globalCss(rules);
```

**원인:** 전역 스타일시트에는 선택자와 규칙을 잇는 구조가 알려져 있어야 합니다.

**해결:** 리터럴 객체나, 빌드가 평가할 수 있는 상수 객체/계산을 전달하세요.

{/* probe: global-object after */}

```tsx
import { globalCss } from '@devup-ui/react'
globalCss({ body: { color: 'red' } })
```

### 알 수 없는 keyframe spread

**API:** css / globalCss / keyframes. **메시지 형식:**

```text
`keyframes()` cannot use `<code>` at build time: its values must be literals, theme tokens or constants, or be computed from them
```

**발생 조건:**

{/* probe: keyframes-spread before */}

```tsx-error
import { keyframes } from '@devup-ui/react';
export const fade = keyframes({ ...frames });
```

**원인:** 빌드는 모든 프레임의 이름과 선언을 알아야 합니다.

**해결:** 프레임을 명시적으로 작성하거나 상수 객체에서 가져오세요.

{/* probe: keyframes-spread after */}

```tsx
import { keyframes } from '@devup-ui/react'
export const fade = keyframes({ from: { opacity: 0 }, to: { opacity: 1 } })
```

### 컴파일할 수 없는 합성 인자

**API:** css / globalCss / keyframes. **메시지 형식:**

```text
Cannot compose `<styles>` at build time: each style must be a rule object, a class, or a condition choosing between them
```

**발생 조건:**

{/* probe: css-compose before */}

```tsx-error
import { css } from '@devup-ui/react';
export const card = css(getStyles());
```

**원인:** 빌드는 알 수 없는 함수 결과의 키를 알아낼 수 없습니다.

**해결:** 알려진 규칙 객체, 클래스, 또는 그 형태 중 하나를 고르는 조건을 합성하세요. 결정적이고 빌드가 읽을 수 있는 헬퍼는 허용됩니다.

{/* probe: css-compose after */}

```tsx
import { css } from '@devup-ui/react'
export const card = css({ color: 'red' })
```

### 선택자나 속성 이름 안의 런타임 interpolation

**API:** css / globalCss / keyframes. **메시지 형식:**

```text
Cannot place `<expression>` at build time: an interpolation in a selector or a property name must be a literal or a constant
```

**발생 조건:**

{/* probe: template-selector before */}

```tsx-error
import { css } from '@devup-ui/react';
export const card = css`& ${selector} { color: red; }`;
```

**원인:** 빌드는 동적 표현식을 선택자나 속성 이름 문법 안에 넣을 수 없습니다.

**해결:** 리터럴 텍스트나 빌드가 읽을 수 있는 상수를 사용하세요. styled 템플릿에도 똑같이 적용됩니다.

{/* probe: template-selector after */}

```tsx
import { css } from '@devup-ui/react'
export const card = css`
  & > p {
    color: red;
  }
`
```

### 다른 코드가 변경하는 스타일 객체

**API:** css / globalCss / keyframes. **메시지 형식:**

```text
`css()` cannot use `<code>` at build time: its styles must be an object literal or a constant object, or be computed from constants
`<binding>` is changed here, so the build cannot read it as a constant
```

**발생 조건:**

{/* probe: changed-object before */}

```tsx-error
import { css } from '@devup-ui/react';
const rules = { color: 'red' };
rules.color = color;
export const card = css(rules);
```

**원인:** const 바인딩이라고 해서 변경되는 객체가 고정된 스타일시트 값이 되지는 않습니다. 오류에는 변경 위치를 가리키는 메모가 포함될 수 있습니다.

**해결:** 스타일 객체를 변경하지 마세요. 동적 값은 요소에 두거나, 정적 값으로 새 상수 객체를 만드세요.

{/* probe: changed-object after */}

```tsx
import { css } from '@devup-ui/react'
const rules = { color: 'red' }
export const card = css(rules)
```

{/* probe: global-element-object after */}

### css()의 잘못된 선택자

**API:** css / globalCss / keyframes. **메시지 형식:**

```text
`css()` cannot use `<code>` at build time: a selector takes styles, an object such as `{ color: 'red' }` or CSS text such as `color: red`
```

{/* probe: selector-css-api after */}

**API:** css / globalCss / keyframes. **메시지 형식:**

## styled

### 잘못된 styled factory 형태

**API:** styled. **메시지 형식:**

```text
`styled()` cannot use `<code>` at build time: it renders a tag, a component or a value naming one, with rule objects or CSS text
```

**발생 조건:**

{/* probe: styled-factory before */}

```tsx-error
import { styled } from '@devup-ui/react';
export const Card = styled(123)({ color: 'red' });
```

**원인:** styled factory는 어떤 태그나 컴포넌트를 렌더링하는지, 어떤 인자가 규칙인지 알아야 합니다.

**해결:** 먼저 태그/컴포넌트를 전달하고, 그다음 규칙 객체나 CSS 텍스트를 전달하세요.

{/* probe: styled-factory after */}

```tsx
import { styled } from '@devup-ui/react'
export const Card = styled('div')({ color: 'red' })
```

### 런타임 규칙 객체 전체

**API:** styled. **메시지 형식:**

```text
`styled()` cannot use `<code>` at build time: its styles must be an object literal or a constant object, or be computed from constants
```

**발생 조건:**

{/* probe: styled-object before */}

```tsx-error
import { styled } from '@devup-ui/react';
export const Card = styled.div({ _hover: rules });
```

**원인:** 런타임 규칙 객체 전체는 알려진 속성의 런타임 값과 달리 키를 알 수 없습니다.

**해결:** 규칙 구조를 명시적으로 유지하세요. 런타임 값에는 &lt;Box \_hover=\{\{ color \}\} /&gt; 같은 스타일 prop을 사용하세요.

{/* probe: styled-object after */}

```tsx
import { styled } from '@devup-ui/react'
export const Card = styled.div({ _hover: { color: 'red' } })
```

### 컴파일할 수 없는 styled 합성

**API:** styled. **메시지 형식:**

```text
Cannot compose `<styles>` at build time: each style must be a rule object, a class, or a condition choosing between them
```

**발생 조건:**

{/* probe: styled-compose before */}

```tsx-error
import { styled } from '@devup-ui/react';
export const Card = styled.div({ color: 'red' }, getStyles());
```

**원인:** 알 수 없는 함수 결과는 스타일시트 선언으로 나눌 수 없습니다.

**해결:** 알려진 객체/클래스나 그중 하나를 고르는 조건을 합성하고, 런타임 차이는 props로 표현하세요.

{/* probe: styled-compose after */}

```tsx
import { styled } from '@devup-ui/react'
export const Card = styled.div({ color: 'red' }, { padding: '4px' })
```

### 지원되지 않는 shouldForwardProp 조건 함수

**API:** styled. **메시지 형식:**

```text
`styled()` cannot use `<code>` at build time: `shouldForwardProp` must be a function of the prop name that compares it with strings, `[...].includes(prop)`, `prop.startsWith(...)` or `isPropValid(prop)`, joined by `!`, `&&` and `||`
```

**발생 조건:**

{/* probe: styled-forward before */}

```tsx-error
import { styled } from '@devup-ui/react';
export const Card = styled.div.withConfig({ shouldForwardProp: name => check(name) })({ color: 'red' });
```

**원인:** 빌드가 필터를 평가하므로, 임의의 런타임 조건 함수로는 어떤 props를 요소에 전달할지 결정할 수 없습니다.

**해결:** 문자열과 비교하거나 includes, startsWith, isPropValid를 사용하고, 이를 !, &&, ||로 결합하세요.

{/* probe: styled-forward after */}

```tsx
import { styled } from '@devup-ui/react'
export const Card = styled.div.withConfig({
  shouldForwardProp: (name) => name !== 'tone',
})({ color: 'red' })
```

### 요소 인자를 호출하는 shouldForwardProp

**API:** styled. **메시지 형식:**

```text
`styled()` cannot use `<code>` at build time: styled-components v6 passes `shouldForwardProp` the element it renders as its second argument, not v5's validator, so calling it fails at runtime. Fix: call `isPropValid(prop)` from `@emotion/is-prop-valid`, or compare the prop with strings
```

**발생 조건:**

```tsx-error
import styled from 'styled-components';
export const Card = styled.div.withConfig({ shouldForwardProp: (prop, valid) => valid(prop) })`color: red;`;
```

**원인:** styled-components v6는 `shouldForwardProp(prop, elementToBeCreated)`를 호출합니다. 두 번째 인자는 렌더링할 태그나 컴포넌트이므로, 태그인 경우 이를 호출하면 오류가 발생합니다.

**해결:** `@emotion/is-prop-valid`의 `isPropValid`를 호출하거나, prop을 문자열과 비교하세요.

```tsx
import isPropValid from '@emotion/is-prop-valid'
import styled from 'styled-components'
export const Card = styled.div.withConfig({
  shouldForwardProp: (prop) => isPropValid(prop),
})`
  color: red;
`
```

### 읽을 수 없는 styled 식별 옵션

**API:** styled. **메시지 형식:**

```text
`styled()` cannot use `<code>` at build time: `target`, `componentId` and a `displayName` beside a `componentId` decide the classes the component renders; write them as literals
`styled()` cannot use `<code>` at build time: styled-components throws on a `componentId` that is not a string; write it as a string
`styled()` cannot use `<code>` at build time: styled-components throws on a truthy `displayName` that is not a string beside a `componentId`; write it as a string
```

**발생 조건:**

```tsx-error
import styled from 'styled-components'
export const Card = styled.div.withConfig({ componentId: makeId() })`
  color: red;
`
```

**원인:** Emotion의 `target`과 styled-components의 `componentId`(둘 다 설정되면 앞에 `displayName`이 붙음)는 요소의 클래스가 되므로, 빌드가 그 텍스트를 알아야 합니다. Emotion이 허용하는 리터럴은 클래스를 추가하지 않는 `''`를 포함해 모두 컴파일됩니다. styled-components는 문자열이 아닌 `componentId`, 그리고 그 옆에 놓인 문자열이 아닌 truthy `displayName`에 대해 오류를 던집니다.

**해결:** 옵션을 리터럴로 작성하세요. `componentId`와 `displayName`은 문자열로 작성합니다.

```tsx
import styled from 'styled-components'
export const Card = styled.div.withConfig({ componentId: 'card' })`
  color: red;
`
```

### 지원되지 않는 withComponent 대상

**API:** styled. **메시지 형식:**

```text
`withComponent()` cannot use `<code>` at build time: it takes one tag name, as `'aside'`, or a component written as a name or `a.b`, as the styled component compiles to a plain function with no `withComponent` at runtime. Fix: pass the tag or component directly, or render the styled component with `as`
`withComponent()` cannot use `<code>` at build time: it takes one tag or component, as options beside it would give the component classes and props the build cannot see. Fix: pass the tag or component alone, or create the component with `styled(tag, options)`
```

**발생 조건:**

```tsx-error
import styled from '@emotion/styled'
const Card = styled('div', { target: 'card' })`
  color: red;
`
export const Link = Card.withComponent('a', { target: 'link' })
```

**원인:** 빌드는 `withComponent`를 새 대상에 같은 클래스를 렌더링하는 컴포넌트로 컴파일합니다. Devup UI나 styled-components의 `styled`로 만든 컴포넌트는 런타임에 `withComponent`가 없으므로, 대상은 태그 이름이거나 이름 또는 `a.b`로 작성한 컴포넌트여야 합니다. Emotion의 `styled`로 만든 컴포넌트는 런타임에 어떤 대상이든 하나를 받습니다. 새 `target`이나 `shouldForwardProp`처럼 대상 옆에 전달한 옵션은 빌드가 볼 수 없는 클래스와 props를 바꾸게 됩니다.

**해결:** 태그나 컴포넌트만 전달하세요. 다른 옵션이 필요하면 `styled(tag, options)`로 컴포넌트를 만드세요.

```tsx
import styled from '@emotion/styled'
const Card = styled('div', { target: 'card' })`
  color: red;
`
export const Link = styled('a', { target: 'link' })`
  color: red;
`
```

**해결:** 스타일 객체, CSS 텍스트, css()가 반환하는 클래스, 이를 반환하는 테마 함수, 또는 이들의 배열/조건을 사용하세요.

### 바인딩 뒤에 숨은 지역 스타일 객체

**API:** Emotion css prop과 ClassNames. **메시지 형식:**


```tsx-error
import { css } from '@emotion/react';
```

**해결:** 객체를 css 안에 직접 작성하거나 const로 선언하세요.

{/* probe: css-prop-local after */}

```tsx
const rules = { color: 'red' }
export function App() {
  return <div css={rules} />
}
```

### 내부를 알 수 없는 styled 컴포넌트를 덮어쓰는 css prop

**API:** Emotion css prop과 ClassNames. **메시지 형식:**

```text
`css` on `<Card>` overrides styles `Card` sets, which the build orders only for a styled component rendering a tag with no attrs or props read, given no spread, `as` or `forwardedAs`: move these styles into `styled(Card)(...)`
```

**발생 조건:**

{/* probe: css-prop-override before */}

```tsx-error
import { css } from '@emotion/react';

```

**원인:** 순서는 attrs, props 읽기, spread, as, forwardedAs가 없는 정적 styled 태그에서만 알 수 있습니다.

**해결:** 덮어쓰는 스타일을 styled(Card)(...)로 옮기세요. 겹치지 않는 css prop에는 이 순서가 필요하지 않습니다.

{/* probe: css-prop-override after */}

```tsx
import '@emotion/react'

import styled from '@emotion/styled'

```

### 다른 코드도 읽는 스타일 선택을 읽는 css prop

**API:** Emotion css prop. **메시지 형식:**

```text
`css` on `<div>` cannot use `<code>` at build time: it chooses among styles the build compiles only when `css` props alone read a `const` holding them: read it only as `css`, or write the choice in the prop
```

**발생 조건:**

```tsx-error
import { css } from '@emotion/react';
export function App({ on }) { const rules = on ? { color: 'red' } : { color: 'blue' }; console.log(rules); return <div css={rules} />; }
```

**원인:** `? :`, `&&`, `||`, `??`로 스타일 객체 중 하나를 고르는 `const`는 선언된 위치에서 컴파일됩니다. 각 객체는 Emotion이 부여할 클래스가 되고, 선택은 여전히 런타임에 실행됩니다. 이는 `css` props만 그 값을 읽을 때에만 안전합니다. 다른 코드는 객체 대신 클래스 이름을 보게 되기 때문입니다. `let`에도 똑같이 적용됩니다.

**해결:** 바인딩을 `css`로만 읽거나, 선택을 prop 안에 작성하세요.

```tsx
export function App({ on }) {
  const rules = on ? { color: 'red' } : { color: 'blue' }
  return <div css={rules} />
}
```

### 스타일을 반환하는 함수의 결과를 읽는 css prop

**API:** Emotion css prop. **메시지 형식:**

```text
`css` on `<div>` cannot use `<code>` at build time: it holds what a call gives, and the function returns a style object, which the build does not run the call to read: write the styles in the prop or in a `const` it reads, or return a class `css()` gives
```

**발생 조건:**

```tsx-error
import { css } from '@emotion/react';
function make() { return { color: 'red' }; }
export function App() { const rules = make(); return <div css={rules} />; }
```

**원인:** 빌드는 호출을 실행하지 않습니다. 객체나 배열 리터럴을 반환하는 모듈의 함수는 스타일을 반환하며, `css` prop은 이를 클래스로 전달할 수 없습니다. 매개변수나 import처럼 빌드가 내부를 볼 수 없는 호출은 여전히 클래스로 전달됩니다.

**해결:** 스타일을 prop 안이나 prop이 읽는 `const`에 작성하거나, 함수가 `css()`의 클래스를 반환하도록 하세요.

```tsx
import { css } from '@emotion/react'
const make = () => css({ color: 'red' })
export function App() {
  const rules = make()
  return <div css={rules} />
}
```

**해결:** \{ css, cx, theme \}만 받고 렌더링할 내용을 바로 반환하는 자식 함수 하나를 사용하고, ClassNames의 속성은 제거하세요.

## 런타임 전용 옵션

alias가 적용되면 `StyleSheetManager`와 `CacheProvider`는 아무 동작도 하지 않습니다. 따라서 이들이 만들어 낼 CSS나 props를 바꾸는 옵션은 조용히 버려지는 대신 위치가 표시된 오류가 됩니다. `target`, `nonce`, `key`, `prepend`처럼 런타임 삽입만 제어하는 옵션은 계속 허용됩니다.

### 런타임에 버려지는 StyleSheetManager 옵션

**API:** styled-components. **메시지 형식:**

```text
`stylisPlugins` of `StyleSheetManager` from `styled-components` runs stylis plugins over the CSS at runtime, which Devup UI does not compile, so the plugins would never reach the stylesheet. Fix: write the CSS the plugins would produce into the styles, or set `importAliases: { 'styled-components': false }` and build with styled-components
```

`shouldForwardProp`(`filters at runtime the props every styled component passes on`)와 `namespace`(`prefixes every selector at runtime`)도 같은 형태로 보고되며, manager에 JSX spread를 쓴 경우(`takes spread props, so whether they set ... cannot be known at build time`)도 마찬가지입니다.

**발생 조건:**

{/* probe: style-sheet-manager before */}

```tsx-error

  <StyleSheetManager stylisPlugins={[rtlPlugin]} shouldForwardProp={isPropValid}>{children}</StyleSheetManager>
);
```

**원인:** Devup UI는 모든 규칙을 빌드 시점에 작성하고 stylis 처리 단계가 없으므로, manager의 플러그인과 prop 필터는 아무 효과 없이 조용히 무시됩니다.

**해결:** 플러그인이 만들어 낼 CSS를 직접 작성하고(예: RTL 플러그인 대신 논리 속성 사용), 각 styled 컴포넌트에 `.withConfig()`로 자체 `shouldForwardProp`을 지정하세요.

{/* probe: style-sheet-manager after */}

```tsx

  shouldForwardProp: (name) => name !== 'tone',
})({ marginInlineStart: 8 })
```

## 플러그인과 설정

아래 메시지는 추출기가 아니라 빌드 플러그인에서 나옵니다. 플러그인은 위의 모든 추출기 진단도 해당 파일의 오류로 전달합니다. 네이티브 파일 시스템 오류나 전송 실패는 플랫폼과 근본 오류에 따라 달라집니다.

### devup.json을 불러올 수 없음

**메시지 형식:**

```text
<file> is not valid JSON: <parser message>. Fix its syntax; Devup UI does not load the theme until it parses.
<file> must hold a JSON object such as { "theme": {} }, not <null | an array | a string | ...>.
devup.json `extends` form a cycle: <file> -> <file> -> <file>. Remove the `extends` entry that points back to an earlier file.
```

**원인:** 테마는 `devup.json`과 그 `extends`에 나열된 모든 파일에서 읽습니다. 대신 빈 테마로 빌드하면 선언되지 않은 테마 변수를 읽는 클래스가 배포됩니다.

**해결:** 메시지가 가리키는 파일을 수정하세요. `extends`에 나열된 파일이 존재하지 않는 것은 오류가 아니며, 아무것도 추가하지 않을 뿐입니다.

### 빌드가 출력할 수 없는 테마 토큰

**메시지 형식:**

```text
theme.colors.<variant>: color token '<name>' is not a valid token name: start with a letter, a digit or '_', then use letters, digits, '-', '_' and '.'
theme.colors.<variant>: color tokens '<a>' and '<b>' both become the CSS variable --<variable>: rename one
theme: color token '<name>' and shadow token '<name>' both become the CSS variable --<variable>: rename one
```

`length`와 `shadow` 토큰도 같은 방식으로, `theme.length.<variant>: length token ...`과 `theme.shadow.<variant>: shadow token ...` 형태로 보고됩니다.

**원인:** 토큰은 CSS 변수가 되므로(`gray.100`은 `--gray-100`), 허용된 문자 밖의 이름은 브라우저가 버리는 CSS를 만들고, 같은 변수가 되는 두 토큰(`a-b`와 `a.b`, 또는 둘 다 `card`라는 이름의 색상 토큰과 `shadow` 토큰)은 하나의 변수를 두 번 설정하게 됩니다.

**해결:** 둘 중 한 토큰의 이름을 바꾸세요. 이름 규칙은 [색상](/docs/devup/colors)을 참고하세요.

### 프로덕션 빌드와 개발 서버

`devup.json`이나 테마 오류가 있으면 프로덕션 빌드(`vite build`, `watch` 없는 webpack 빌드, `rsbuild build`, `next build`, `Bun.build`)는 위 메시지와 함께 실패합니다. 개발 서버는 계속 실행되므로 서버가 파일을 감시하는 동안 수정할 수 있습니다. Vite는 오류를 출력하고 오류 오버레이에 표시하며, webpack, Rsbuild, webpack을 사용하는 Next.js는 테마가 다시 로드될 때까지 이를 컴파일 오류(`[devup-ui] <message>`)로 보고합니다. 그때까지 테마는 비어 있습니다.

프로젝트 루트에 `devup.json`이 없고 `devupFile`도 설정하지 않았지만 작업 디렉터리에 해당 파일이 있으면, 플러그인은 그 파일을 읽고 경고를 한 번 출력합니다.

```text
[devup-ui] Found devup.json relative to the working directory (<cwd file>), not the project root (<root>). ...
```

`devup.json`을 프로젝트 루트로 옮기거나 `devupFile`을 설정하세요. 자세한 내용은 [devup.json](/docs/devup/devup-json)을 참고하세요.

### Next.js 코디네이터 실패

Turbopack을 사용할 때 Next.js 플러그인은 빌드를 위해 직접 시작한 코디네이터 프로세스에서 파일을 컴파일하며, 로더가 각 파일을 그곳으로 보냅니다. 코디네이터는 따로 설정하지 않습니다. 아래 메시지는 코디네이터가 실행 중이 아니거나, 응답하지 않거나, 작업을 끝내지 못했다는 뜻입니다.

```text
Coordinator port file not found: <port file>. The devup-ui coordinator for this build is not running (or exited). ...
Coordinator unreachable at 127.0.0.1:<port> (<owner>, port file <port file>): <cause>. ...
```

코디네이터가 종료되었거나, 다른 `next dev`나 `next build`가 이를 대체한 경우입니다. 개발 서버나 빌드를 다시 시작하고, 하나의 `distDir`에서 `next dev`와 `next build`를 동시에 실행하지 마세요. 함께 실행해야 한다면 각각 별도의 `distDir`을 지정하세요.

```text
Coordinator CSS error: <status>: [devup-ui] coordinator: <bucket or base sheet> is incomplete (<reason>); refusing to serve partial CSS. Files not extracted: <files>.
```

프로덕션 빌드가 끝내 추출되지 않은 파일을 기다렸으므로, 해당 규칙이 빠진 스타일시트를 배포하는 대신 실패합니다. 이는 플러그인이 예상한 파일과 Next.js가 컴파일한 파일이 다르다는 뜻이므로, 파일 목록과 함께 제보해 주세요.

`Coordinator error`와 `Coordinator response missing code`는 코디네이터가 결과나 오류 메시지 없이 파일에 응답했다는 뜻입니다. 빌드를 다시 시작하고, 계속 발생하면 제보해 주세요.

### 빌드 플러그인 누락

`Cannot run on the runtime`은 추출기 빌드 진단이 아니라 플레이스홀더 예외입니다. 컴파일 시점 컴포넌트나 헬퍼가 변환되지 않은 채 실행되었다는 뜻입니다. 알맞은 Devup UI 빌드 플러그인을 설정하고, 해당 파일이 추출 대상에 포함되는지 확인하세요. 스타일링 런타임을 추가하는 방식으로 해결하지 마세요.

### 제거된 바인딩의 런타임 읽기를 ESLint로 잡기

`devup/no-runtime-read` 규칙은 지원되는 호출/렌더링 밖에서 읽힌 컴파일 시점 바인딩을 빌드 전에 보고합니다. 린트 메시지는 마침표로 끝나지만 추출기 메시지는 그렇지 않습니다. 두 경우 모두 같은 직접 호출로 고칩니다.

```text
`<binding>` is read at runtime, where it does not exist: the build compiles it only where it is called or rendered.
```

```tsx-error
import { css } from '@devup-ui/react'
consume(css)
```

```tsx
import { css } from '@devup-ui/react'
const card = css({ color: 'red' })
```

그 밖의 ESLint 진단, alias 유지 경고, StyleX 축약형 경고는 추출기 빌드 오류가 아닙니다. 빌드가 인식하지 못하는 Tailwind 클래스는 그대로 유지되며, 새로운 빌드 오류 유형을 만들지 않습니다.
