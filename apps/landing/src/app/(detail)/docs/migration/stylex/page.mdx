# StyleX

`@stylexjs/stylex` needs no alias configuration — the extractor recognises the package directly, through the default import, a namespace import, or named imports.

These are alternative upstream import forms:

```ts
import * as sx from '@stylexjs/stylex'
import stylex from '@stylexjs/stylex'
import { positionTry, viewTransitionClass } from '@stylexjs/stylex'

positionTry({ top: 0 })
viewTransitionClass({ old: { opacity: 0 } })
stylex.positionTry({ top: 0 })
sx.viewTransitionClass({ old: { opacity: 0 } })
```

You can also use the real Devup UI API through named or namespace imports from `@devup-ui/react/stylex`, the root named `stylex` export, or `devup.stylex` through a root namespace import. These are alternative forms, not imports you need to combine:

```ts
import * as devup from '@devup-ui/react'
import { stylex as sx } from '@devup-ui/react'
import * as stylex from '@devup-ui/react/stylex'
import { positionTry, viewTransitionClass } from '@devup-ui/react/stylex'

sx.positionTry({ top: 0 })
devup.stylex.viewTransitionClass({ old: { opacity: 0 } })
positionTry({ top: 0 })
viewTransitionClass({ old: { opacity: 0 } })
stylex.positionTry({ top: 0 })
```

The dedicated `/stylex` subpath has no default export. The root exports the `stylex` namespace, not individual `positionTry` or `viewTransitionClass` functions. `@devup-ui/react/compat/stylex` is a types-only reference for upstream imports, not a runtime entrypoint. All styling APIs must be compiled by a Devup UI build plugin; their placeholders throw if called at runtime.

## Styles and props

`create()` becomes a namespace-to-class-name object and `props()` becomes the attributes to spread:

```tsx
import stylex from '@stylexjs/stylex'

const styles = stylex.create({
  base: { display: 'inline-block' },
})
const colors = stylex.create({ red: { color: 'red' }, blue: { color: 'blue' } })

const el = <div {...stylex.props(styles.base, colors[color])} />
```

```tsx
const styles = { base: 'a' }
const colors = { red: 'b', blue: 'c' }

const el = <div {...{ className: `a ${colors[color] || ''}` }} />
```

Computed access such as `colors[color]` is resolved against the object the `create()` call was rewritten into, so every generated atom stays reachable. `stylex.attrs()` behaves the same but emits `class` instead of `className`.

Numbers use valid CSS units: `fontSize: 16` is `16px`, `transitionDuration: 300` is `300ms`, and unitless properties such as `lineHeight` stay as written. A number passed to a dynamic `create()` style gets the same unit at runtime through its generated CSS variable, without a styling runtime.

Accepted argument shapes:

```tsx
stylex.props(styles.base) // member access
stylex.props(styles['base']) // literal key
stylex.props(colors[color]) // runtime key
stylex.props([styles.a, styles.b]) // StyleXArray, nestable
stylex.props(on && styles.active) // conditional
stylex.props(styles?.base) // optional chaining
```

## Variables and themes

Generated names in these examples (`--a`, `--b`, `c` and `d`) are illustrative and opaque. Variable references encode the defining file and member; the old counter-based spellings are not promised.

```tsx
const colors = stylex.defineVars({ primary: 'blue', secondary: 'grey' })
const dark = stylex.createTheme(colors, { primary: 'navy' })
const styles = stylex.create({ box: { color: colors.primary } })

const el = <div {...stylex.props(dark, styles.box)} />
```

```css
:root {
  --a: blue;
  --b: grey;
}
.c {
  --a: navy;
}
.d {
  color: var(--a);
}
```

```tsx
const colors = { primary: 'var(--a)', secondary: 'var(--b)' }
const dark = 'c'
const styles = { box: 'd' }
const el = <div {...{ className: 'c d' }} />
```

`createThemeContract()` produces the same references without publishing a `:root` block, and `defineConsts()` inlines its values into the `create()` calls that read them.

A variable or theme value can depend on at-rules, with an optional `types.*()` wrapper. Each set of conditions becomes one block after the unconditional values, and nested conditions come after the ones they refine, so the more specific value wins:

```tsx
const DARK = '@media (prefers-color-scheme: dark)'

const colors = stylex.defineVars({
  text: { default: 'black', [DARK]: 'white' },
  accent: stylex.types.color({ default: 'blue', [DARK]: 'lightblue' }),
})
const dracula = stylex.createTheme(colors, {
  text: { default: 'purple', [DARK]: 'pink' },
})
```

```css
:root {
  --a: black;
  --b: blue;
}
@media (prefers-color-scheme: dark) {
  :root {
    --a: white;
    --b: lightblue;
  }
}
.c {
  --a: purple;
}
@media (prefers-color-scheme: dark) {
  .c {
    --a: pink;
  }
}
```

Conditions are `default`, `@media`, `@supports` and `@container` keys, and `null` leaves a variable unset under its condition. A value that is not static is a build error naming it; pseudo-class keys count as not static, because a variable is set on `:root` or a theme class, not on the element being styled.

As StyleX requires, variables usually live in a `.stylex.ts` file and are imported where they are used. Imports resolve like the bundler resolves them, and the importing file reads the same custom properties, theme classes and constants that the defining file generates:

```tsx
// tokens.stylex.ts
export const colors = stylex.defineVars({ primary: 'blue' })
export const spacing = stylex.defineConsts({ gap: '8px' })

// Button.tsx
import { colors, spacing } from './tokens.stylex'

const dark = stylex.createTheme(colors, { primary: 'navy' })
const styles = stylex.create({
  box: { color: colors.primary, marginTop: spacing.gap },
})
```

A value in `create()` that this file's own functions compute from constants with exact built-ins, such as `double(SIZE)`, is computed at build time; another module's code never runs, and code whose result is not certain (`Date`, `Math.random`, `Math.sin`, locale methods, `new`, `this`...) is not run. A value only known at runtime, such as a prop or state, is a build error naming it. In `create()` styles, pass runtime values through a dynamic style (`(color) => ({ color })`), which becomes a CSS variable instead.

Calls accept input the build can resolve exactly. An unresolved spread or computed key, runtime leaf, non-object argument, unsupported property or slot, or malformed call is a located build error. Statically resolvable spreads and computed keys are not rejected merely for using that syntax. Transition declarations do not accept dynamic style functions.

`stylex.props()` accepts styles compiled elsewhere — a `style` prop a parent passes, a spread, another module's namespaces — and joins their class names at runtime; namespaces of this file resolve at build time.

## Position fallbacks and view transitions

```tsx
import * as stylex from '@devup-ui/react/stylex'

const fallback = stylex.positionTry({ top: 0, width: 100 })
const transition = stylex.viewTransitionClass({
  group: { animationDuration: 300 },
  imagePair: { borderRadius: 16 },
  old: { opacity: 0 },
  new: { animationDuration: '300ms', fontWeight: 700 },
})
const styles = stylex.create({
  tooltip: { positionTryFallbacks: fallback },
  card: { viewTransitionClass: transition },
})
```

```css
@position-try --POSITION_ID {
  top: 0;
  width: 100px;
}
::view-transition-group(*.TRANSITION_ID) {
  animation-duration: 300ms;
}
::view-transition-image-pair(*.TRANSITION_ID) {
  border-radius: 16px;
}
::view-transition-old(*.TRANSITION_ID) {
  opacity: 0;
}
::view-transition-new(*.TRANSITION_ID) {
  animation-duration: 300ms;
  font-weight: 700;
}
```

`POSITION_ID` and `TRANSITION_ID` are symbolic placeholders for opaque deterministic generated names, not literal output or promised short `a`/`b` allocations. Each name encodes the file identity, API domain and canonical content. Names are longer than counter-based atom names; there are no arrival counters or allocation-history dependencies. The same file and canonical content share a name, while different content does not. Position declarations are sorted when forming canonical content, so changing their enumeration order preserves sharing. View transitions preserve slot and declaration enumeration order in their canonical content, so reordering them can change the name. An absent slot and an empty slot are distinct inputs.

`viewTransitionClass()` accepts only the optional `group`, `imagePair`, `old` and `new` slots, each containing a flat declaration object. The output targets the four class-qualified view-transition pseudo-elements, not an ordinary `.TRANSITION_ID` rule. `positionTry()` accepts the supported camelCase position, inset, margin, sizing and self-alignment properties. Numeric lengths become px, numeric durations become ms, and unitless values such as `fontWeight: 700` stay unitless; Devup spacing multipliers do not apply. Devup preserves valid CSS rather than reproducing upstream extra position declarations or incorrect numeric units.

Declaration leaves may be static strings or numbers. Known `null`, `undefined` and `false` leaves omit the declaration; they do not make a slot optional at runtime. A supplied view slot must still be an object, not `null`, `undefined`, `false` or a scalar. Known `true`, arrays, plain objects and functions used as declaration leaves are errors. Nested `default`, `:hover`, media, supports or container condition objects are not transition declaration syntax. Select distinct statically defined fallback or transition strings in a supported enclosing style instead. API, function and namespace values cannot escape uncompiled into JavaScript.

## Value helpers

Within `create()` styles, `firstThatWorks()` emits its fallbacks in CSS order, `types.*()` unwraps to the inner value, and `include()` merges another namespace's classes. `create()` style values may be plain literals, condition objects (`{ default, ':hover', '@media ...' }`), or arrow functions, which become CSS variables bound at the call site. These forms do not extend the flat declaration contract of `positionTry()` or `viewTransitionClass()`.

For example, ordinary pseudo-class styles use property conditions inside `create()`:

```tsx
const states = stylex.create({
  button: { color: { default: 'black', ':hover': 'blue' } },
})
```
