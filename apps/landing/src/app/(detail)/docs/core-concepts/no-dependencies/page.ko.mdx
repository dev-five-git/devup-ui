# 의존성 없음

Devup UI는 추가 UI 런타임 코드 없이 순수한 React 소스 코드를 변환합니다.

이 섹션에서는 “의존성 없음”이 실제로 무엇을 의미하는지, 왜 중요한지, 그리고 Devup UI가 클라이언트 측 스타일 엔진, 추가 플러그인, 수동 사전 생성 단계 없이 이를 어떻게 달성하는지 설명합니다.

## 동기

- 많은 CSS-in-JS 라이브러리는 스타일을 계산하거나, `<style>` 태그를 삽입하거나, 변수를 해석하기 위해 런타임에 JavaScript에 의존합니다.
- 동적 값(예: 변수, 표현식)을 사용하면 이러한 솔루션은 흔히 런타임 의존성으로 되돌아갑니다. 이는 비용을 다시 불러오는 부분적인 해결책입니다.
- Next.js 같은 프레임워크에서는 이런 런타임 스타일 시스템을 RSC(React Server Components) 안에서 사용할 수 없는 경우가 많습니다.

그래서 저희는 질문했습니다. 추가 UI 런타임 코드 없이, RSC에서도 동작하는 진정한 제로 런타임 CSS를 제공할 수 있을까?

저희의 접근 방식은 정적 분석에 기반합니다. 코드가 빌드되어 배포되었다면 그 코드에 최종 답이 담겨 있어야 하며, 클라이언트에서 추가 계산이 필요하지 않아야 합니다.

## “의존성 없음”의 의미

- 스타일링을 위한 UI 런타임 코드가 번들에 추가되지 않습니다.
- 추가 플러그인, 사전 생성 스크립트, PostCSS 설정이 필요하지 않습니다.
- 순수한 React가 그대로 기준이 되며, 스타일은 빌드 시점에 정적 CSS로 컴파일됩니다.
- 클라이언트 측 스타일 엔진을 사용할 수 없거나 사용하고 싶지 않은 RSC와 엣지/런타임 환경에서도 동작합니다.

## 어떻게 동작하나요?

1. Rust 기반 도구로 React 소스를 AST로 파싱합니다.
2. 정적 분석을 수행해 컴포넌트와 props에서 모든 스타일 의미를 추출합니다.
3. 스타일을 해석하고 중복을 제거하여 짧은 원자적 클래스 이름을 생성합니다.
4. 클래스 이름이 적용된 새 AST와, 최소한의 규칙 집합이 담긴 CSS 가상 파일을 내보냅니다.
5. 번들러가 정적 CSS와 클래스가 적용된 마크업을 내보냅니다. 클라이언트 측 스타일 엔진은 없습니다.

## 호환성

- Next.js(RSC 포함): 런타임 스타일 엔진 없이 안전하게 사용할 수 있습니다.
- Vite, Rsbuild, Webpack: 공식 플러그인으로 지원합니다.
- DOM/JS 기반 스타일 삽입을 제한하는 서버 우선 환경과 엣지 환경에서도 동작합니다.

## 클래스 이름 규칙

- 클래스 이름은 숫자로 시작하지 않습니다(CSS 제약을 만족하기 위해).
- 안전성을 유지하면서 클래스 이름 길이를 최소화합니다.
  예를 들어 `ad` 같은 토큰은 콘텐츠 차단기에 걸릴 수 있으므로, 필터와 일치하지 않도록 대신 `a-d`를 내보냅니다.
- 일반적인 광고 차단기 휴리스틱을 피하기 위해 의심스러운 토큰에 하이픈(`-`)을 넣어 나눕니다.
- 매핑 예시:
  - `ad` → `a-d`
- 적용 범위: Devup UI가 생성한 원자적 클래스 토큰에만 적용되며, 사용자가 전달한 `className` 문자열은 바꾸지 않습니다.
- 허용되는 문자에는 `a`–`z`, `az`, `a0` 같은 조합, 그리고 안전한 위치의 하이픈/밑줄이 포함됩니다.

## 사용 시 장점

Devup UI는 CSS-in-JS의 편리함과 정적 CSS의 성능을 결합하여, 추가 UI 런타임 의존성 없이 두 가지 장점을 모두 제공합니다.

1. **제로 런타임**: 모든 스타일이 빌드 시점에 정적 CSS로 컴파일됩니다.
2. **중복 제거**: 같은 스타일은 한 번만 생성되어 전역에서 재사용됩니다.
3. **성능**: Rust 기반 파이프라인이 빠르고 확장 가능한 빌드를 제공합니다.
4. **더 작은 번들**: 중복 클래스도, 스타일링을 위한 UI 런타임 코드도 없습니다.
