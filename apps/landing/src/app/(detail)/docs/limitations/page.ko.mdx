# 지원 문법과 제한 사항

Devup UI는 빌드 시점에 스타일을 컴파일하며 스타일링 런타임을 배포하지 않습니다. 빌드가 알 수 있는 것은 모두 컴파일되고, 알 수 없는 것은 요소의 CSS 변수로 유지되거나, 파일·줄·열, 해당 코드, 그리고 대신 필요한 것을 알려 주는 빌드 오류로 보고됩니다. 조용히 누락되는 것은 없으며, 출력은 모든 빌드에서 동일합니다.

이 페이지에서는 무엇이 컴파일되는지, 무엇이 작성한 그대로 유지되는지, 그리고 제한이 어디에 있는지 설명합니다.

## 빌드 시점에 지원하는 문법

| 패턴                                                           | 결과                                                      |
| -------------------------------------------------------------- | --------------------------------------------------------- |
| 리터럴, 테마 토큰, 상수를 사용하는 스타일 props                | 정적 클래스                                               |
| 런타임 값(props, state)을 사용하는 스타일 props                | `style`에서 설정한 CSS 변수를 읽는 클래스                 |
| 반응형 배열, `_hover`를 비롯한 선택자, 그리고 둘의 조합        | 브레이크포인트와 선택자별 클래스                          |
| 조건식(`a ? b : c`, `a && b`, `a \|\| b`, `a ?? b`)            | 분기마다 하나의 클래스, 런타임에 선택                     |
| 파일 안에 있거나 import한, `const`로 선언한 상수               | 객체, 배열, enum, 계산된 상수를 포함해 작성한 그대로 읽음 |
| `css()`, `globalCss()`, `keyframes()`                          | 정적 CSS. 값은 빌드 시점에 알 수 있어야 함                |
| 모든 형태의 `styled()`, `.attrs()`, `as`, `withComponent`      | 정적 클래스와 함께 태그를 렌더링하는 컴포넌트             |
| styled-components / Emotion 테마 읽기(`p.theme.a.b`)           | `ThemeProvider`가 설정하는 `var(--a-b)`                   |
| Emotion `css` prop, `<ClassNames>`, `jsx`, JSX 런타임 pragma   | `className`과 `style`로 컴파일                            |
| 컴포넌트 선택자(`${Child} { ... }`, `[Child]`)                 | 선택된 컴포넌트에 붙는 짧은 마커 클래스                   |
| vanilla-extract `style`, `globalStyle`, `keyframes`            | 정적 CSS                                                  |
| StyleX `create`, `props`, `attrs`, `defineVars`, `createTheme` | 키 단위로 병합된 정적 CSS                                 |
| `className` 안의 Tailwind v4 클래스                            | 정적 클래스. 알 수 없는 클래스는 작성한 그대로 유지       |

## 스타일 덮어쓰기 규칙

빌드가 알 수 있는 스타일을 조합하면, 원래 라이브러리에서 런타임에 동작하는 것처럼 같은 속성, 선택자, 브레이크포인트, 레이어에 대해 뒤에 오는 부분이 앞선 부분을 대체합니다. 이 규칙은 다음에 적용됩니다.

- `css(a, b)`, 그리고 파일이 `css()`에 바인딩한 클래스를 사용하는 Emotion의 `cx(a, b)`
- 파일이 정의한 styled 컴포넌트를 확장하는 `styled(Base)`, 그리고 `.attrs()`
- vanilla-extract `style([a, b])`, StyleX `props(a, b)`
- 뒤에 명시적 props가 오는 JSX spread, 그리고 `className`과 함께 쓴 Emotion `css` prop

반응형 값은 항상 반응형이 아닌 값 뒤에 작성되므로, 클래스가 스타일시트의 어디에 놓이든 브레이크포인트 값이 기본값을 덮어씁니다.

### 캐스케이드가 결정하는 경우

일부 조합은 런타임에만 일어나므로 빌드가 병합할 수 없습니다. 이 경우 결과는 코드에서 각 부분을 작성한 순서가 아니라 CSS 명시도와 스타일시트 순서를 따릅니다.

- props로 전달된 `className`, 외부 클래스(CSS Modules, 디자인 시스템) 또는 런타임에 만들어진 클래스 문자열이 Devup UI 클래스와 합쳐지는 경우
- 빌드가 읽을 수 없는 `styled()` base(`let`, 함수 결과, 다른 패키지의 컴포넌트). 이 base는 계속 감싸진 채로 남습니다
- 알 수 없는 spread props. 작성한 그대로 전달됩니다
- 빌드가 키 단위로 읽을 수 없는 StyleX 인자(다른 모듈의 네임스페이스, `include()`)

어느 쪽이 적용되는지가 중요하다면, 변형을 prop, variant(`cond ? a : b`) 또는 파일이 정의한 `styled()` 확장으로 전달하여 빌드가 양쪽을 모두 볼 수 있게 하세요.

## 브라우저 지원

생성된 CSS는 [Baseline 2024](https://web.dev/baseline)를 대상으로 합니다. 색상 테마에는 `light-dark()`, 캐스케이드 레이어에는 `@layer`, 그룹 선택자에는 `:is()`를 사용합니다. 이 기능이 없는 구형 브라우저는 지원하지 않습니다.

## 직접 만든 컴포넌트의 `css` prop

Emotion `css` prop은 `className`과 `style`로 컴파일됩니다. 이 prop을 받는 직접 만든 컴포넌트는 대신 이 두 props를 받으므로, 렌더링하는 요소에 둘 다 전달해야 합니다.

```tsx
function Card({ className, style, children }) {
  return (
    <div className={className} style={style}>
      {children}
    </div>
  )
}

const example = <Card css={{ color: 'red', padding: width }} />
```

`width` 같은 동적 값은 `style`에서 설정되는 CSS 변수가 되므로, `style`을 버리는 컴포넌트에서는 그 값이 사라집니다.

## 런타임 전용 API

| API                                                          | 동작                                                                                                                              |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `ServerStyleSheet`, `StyleSheetManager`, `CacheProvider`     | 허용되지만 아무 동작도 하지 않습니다. Devup UI가 빌드 시점에 실제 스타일시트를 작성합니다. `CacheProvider`는 `value`를 무시합니다 |
| stylis 플러그인(`stylisPlugins`)                             | `StyleSheetManager`나 `createCache()`에 전달하면 빌드 오류입니다. 빌드 시점에는 stylis 처리 단계가 없습니다                       |
| `StyleSheetManager` `shouldForwardProp`, `namespace`         | 빌드 오류입니다. 컴포넌트마다 `.withConfig({ shouldForwardProp })`를 사용하고, 범위는 직접 작성하세요                             |
| 빌드가 이름을 알 수 없는 props에 대한 `shouldForwardProp`    | 빌드 시점에만 평가됩니다. spread나 호출하는 쪽이 전달한 prop은 거부되더라도 요소에 전달됩니다                                     |
| `@emotion/css` `cache`, `flush`, `hydrate`, `sheet`          | `@emotion/css`에 그대로 남습니다. 런타임에 삽입된 스타일에 대해 동작합니다                                                        |
| `@emotion/css/create-instance`                               | `@emotion/css`에 alias가 설정된 동안에는 빌드 오류입니다. `css`, `cx` 등은 `@emotion/css`에서 import하세요                        |
| `@emotion/react` `ThemeContext`, `withEmotionCache`, `* as`  | `@emotion/react`에 alias가 설정된 동안에는 빌드 오류입니다. Devup UI가 컴파일하는 항목을 이름으로 import하세요                    |
| `ThemeProvider`                                              | 바꾸는 변수를 `display: contents` `<div>`에 선언합니다. 가장 바깥쪽 provider는 `:root`에도 선언합니다                             |
| `jest-styled-components`, `@emotion/jest`, React Native 타깃 | 지원하지 않습니다                                                                                                                 |
| vanilla-extract `recipes`, `sprinkles`                       | alias가 설정된 동안에는 어떤 방식으로 불러오든(import, re-export, `require()`, `import()`) 빌드 오류입니다                        |
| vanilla-extract `dynamic`                                    | `@vanilla-extract/css`에 alias가 설정된 동안에는 빌드 오류입니다. 스타일 prop을 사용하세요                                        |

## 알려진 제한 사항

- export된 styled 컴포넌트는 컴파일될 때, 자기 파일의 어떤 선택자도 그 컴포넌트를 지칭하지 않더라도 짧은 마커 클래스(`a--b`) 하나를 갖습니다. 이 컴포넌트를 import하는 모듈이 그것을 선택(`${Child} { ... }`)하거나 확장할 수 있는데, 각 파일은 어떤 파일이 자신을 import하는지 모른 채 빌드되므로 이 클래스가 처음부터 요소에 있어야 합니다. Vite 또는 webpack 플러그인(Turbopack을 사용하지 않는 Next.js 포함)을 사용한 일회성 프로덕션 빌드에서는 모든 모듈이 컴파일된 뒤 이 클래스를 다시 제거합니다. 빌드 시작 시의 스캔은 읽은 각 파일이 무엇을 선택하는지 보고하고, 각 변환은 해당 모듈이 무엇을 선택하는지 보고하며, 어느 쪽 목록에도 없고 어떤 모듈도 직접 작성하지 않은 마커는 출력 청크에서 제거됩니다. 어떤 모듈이 컴포넌트를 선택하지만 스캔이 그 모듈을 읽지 못한 경우(가상 모듈, MDX처럼 다른 도구가 먼저 컴파일하는 파일, `require.context`, `import.meta.glob` 또는 스캔이 인자를 읽을 수 없는 계산된 `import()`로 불러오는 파일, 함수 `entry`로만 도달하는 파일처럼 스캔 대상 루트와 엔트리 밖에 있는 파일), 빌드는 모든 마커를 유지하고 해당 모듈과 이유를 각각 명시하는 경고를 출력합니다. 개발 서버, watch 빌드, Turbopack, 그리고 Rsbuild와 Bun 플러그인은 모든 마커를 유지합니다. 파일 안에서만 쓰는(export하지 않은) styled 컴포넌트는 그 파일의 선택자가 지칭할 때만 마커를 가지므로, 그 파일에서 렌더링되거나 확장되기만 하는 비공개 컴포넌트에는 마커가 없습니다.
- 다른 모듈에서 정의한 클래스, `keyframes` 이름, styled 컴포넌트는 빌드 시점 값으로 읽히지 않습니다. 그 이름은 해당 파일이 빌드된 뒤에야 알 수 있기 때문입니다. 사용하는 파일에서 선언하거나, 스타일 prop에서 읽으세요.
- `css()`, `globalCss()`, `keyframes()`에는 CSS 변수를 설정할 요소가 없으므로, 이곳의 런타임 값은 빌드 오류입니다. 스타일 prop으로 옮기세요.
- styled-components나 Emotion의 스타일 함수는 테마를 `theme.a.b`(또는 `theme.a[2]`) 형태로만 읽을 수 있습니다. 호출, 테마 전체 읽기, 런타임 키는 빌드 오류입니다.
- CSS 변수는 설정될 요소가 필요하므로, `theme`을 받은 `ThemeProvider`는 자식들을 `<div style="display: contents">`로 감싸 렌더링합니다(`theme`이 없으면 렌더링하지 않습니다). 레이아웃에는 영향을 주지 않지만 여전히 요소이므로, 특정 자식만 허용되는 위치(`<table>`, `<tr>`, `<select>`, `<ul>` 내부)에서는 유효하지 않으며, `>`, `+`, `:first-child` 같은 선택자에서는 부모와 자식 사이에 끼어듭니다. 이런 구조 바깥에 provider를 두세요.
- 테마 키는 CSS 변수 이름의 일부가 되므로(`theme.a.b`는 `--a-b`), `ThemeProvider`는 변수 이름이 될 수 없는 키(예: `'brand color'`), 같은 변수를 만드는 두 경로(`{ a: { b } }`와 `'a-b'`), 자기 자신을 포함하는 테마에 대해 예외를 던집니다. `null`과 `undefined` 값은 아무것도 선언하지 않습니다.
- `<ClassNames>` 안에서 `cx(getClass())`는 빌드 오류입니다. 결과를 먼저 변수에 담으면 클래스로 합쳐집니다.
- `withComponent`는 태그 이름, 또는 이름이나 `a.b` 형태로 작성한 컴포넌트를 받습니다. Devup UI나 styled-components의 `styled`로 만든 컴포넌트에서는 `withComponent(make())`처럼 런타임에만 알 수 있는 대상이 빌드 오류입니다. 이런 컴포넌트는 `withComponent`가 없는 일반 함수로 컴파일되기 때문입니다. 대상을 직접 전달하거나 `as`로 렌더링하세요. Emotion의 `styled`로 만든 컴포넌트는 런타임에도 `withComponent`를 받으므로 어떤 대상이든 하나는 동작합니다. 대상과 함께 전달한 옵션은 빌드 오류입니다.
- `.mdx` 파일은 원본 MDX 상태가 아니라 MDX 플러그인이 JavaScript로 컴파일한 뒤에 추출됩니다. Vite(`@mdx-js/rollup`), webpack과 Rsbuild(`@mdx-js/loader`, `@rsbuild/plugin-mdx`) 플러그인, 그리고 webpack을 사용하는 Next.js(`@next/mdx`)는 MDX 단계를 이후 단계에서 실행합니다. Vite는 `post` 변환에서, webpack과 Rsbuild는 `post` 로더에서 실행합니다. Turbopack을 사용하는 Next.js(`@next/mdx`)는 컴파일된 문서를 추출합니다. `@next/mdx`가 출력의 이름을 `.tsx`로 바꾸고 Turbopack이 그 파일에 소스 규칙을 다시 실행하므로, `withMDX`와 `DevupUI` 중 어느 쪽이 다른 쪽을 감싸든 동작합니다. 프로덕션 Turbopack 빌드는 문서가 컴파일되기 전에 추출할 수 없으므로, 스타일시트는 MDX 라우트 파일(`pageExtensions`에 `mdx`가 있을 때)과, 그 파일들 및 컴파일된 소스가 상대 경로로 import하는 문서를 기다립니다. 경로 alias로만 import된 문서는 기다리지 않습니다. Bun 플러그인은 아직 MDX를 추출하지 않습니다. 빌드 전에 클래스 이름을 예약하는 스캔은 JavaScript와 TypeScript 모듈만 읽으므로, 문서 자체의 클래스는 문서가 컴파일될 때 이름이 정해집니다. Devup UI 스타일이 필요한 컴포넌트는 `.tsx` 모듈에 두고 문서에서 사용하세요.
- Turbopack을 사용하면 Next.js가 해석된 설정을 `.next/required-server-files.{js,json}`과 standalone `server.js`에 복사하므로, 두 Devup UI 로더 규칙(약 500바이트이며 앱 크기와 관계없이 같고 로컬 경로를 포함하지 않음)이 서버 출력에 함께 포함됩니다. 현재는 이를 안전하게 제거할 수 없습니다. Next.js는 플러그인이 등록할 수 있는 어떤 훅보다도 먼저 설정을 복사하며, 그 복사본에서 번들러 설정을 빼는 유일한 옵션은 서버가 배포 id를 읽는 방식도 바꾸기 때문입니다([vercel/next.js#102045](https://github.com/vercel/next.js/discussions/102045)). Webpack 빌드는 여기에 아무것도 추가하지 않습니다.
- 플러그인은 작업 디렉터리의 `tsconfig.json`(또는 `jsconfig.json`)에서 `jsxImportSource`를 읽습니다. `importAliases: { '@emotion/react/jsx-runtime': false }`로 끌 수 있습니다.
- 가장 바깥쪽 `ThemeProvider`는 자신의 `<div>`보다 먼저 렌더링되는 `<style>` 요소 안에서 테마를 `:root`에도 선언하므로, `html`, `body`, `:root`에 대한 `createGlobalStyle`과 `<Global>` 규칙도 테마를 읽습니다. 중첩된 provider는 자신의 하위 트리만 바꿉니다. 가장 바깥쪽 provider가 여러 개 나란히 있으면 모두 `:root`에 작성하며, 문서에서 마지막에 오는 것이 적용됩니다. `<style>` 요소는 provider를 담은 요소의 `textContent`에도 포함됩니다.
- Bun 플러그인은 `Bun.build`에서와 마찬가지로 런타임에서도 ES 모듈과 CommonJS를 가리지 않고 `.ts`, `.mts`, `.cts`, `.tsx`, `.jsx`, `.mjs`, `.js`, `.cjs` 파일을 컴파일합니다. `require()`와 `import`는 CommonJS 모듈의 export를 유지합니다. `node_modules` 안에서는 `@devup-ui` 패키지와 `include` 옵션에 나열한 패키지의 `.js`와 `.cjs` 파일만 컴파일합니다. Bun 런타임 플러그인은 매칭한 모든 파일의 소스를 반환해야 하고 Bun은 그 소스를 ES 모듈로 실행하므로, 런타임에서 플러그인은 CommonJS 모듈을 직접 실행하고 그 `module.exports`를 export하는 ES 모듈을 Bun에 넘깁니다.
- 런타임만 계산할 수 있는 코드(그 밖의 전역 객체, `Date`, `Math.random`, `new`, 클래스, 비동기 코드)는 빌드가 실행하지 않습니다. 요소에서는 CSS 변수로 유지되고, 그 밖의 위치에서는 빌드 오류입니다.

## 빌드 오류

모든 빌드 오류는 위치와 빌드에 필요한 것을 명시합니다.

```
src/App.tsx:6:18: `css()` cannot use `width` at build time: its values must be literals, theme tokens or constants, or be computed from them
src/Card.tsx:3:36: `css` on `<div>` cannot use `getStyles()` at build time: it must be a style object, CSS text, a class `css()` gives, or a function of the theme giving one, or an array or condition of them
```

문제가 여러 개 있는 파일은 소스 순서대로 한 번에 모두 보고합니다.

API별로 정리한 빌드 오류는 [빌드 오류](/docs/build-errors)를 참고하세요.
